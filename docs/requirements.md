# AutoUP 需求纪要（2026-09-08 采访定稿）

> 本文件是 AutoUP 迭代的唯一需求基准。开发过程中的取舍若偏离本文件，须先更新本文件再改代码。
> 前身：AutoYY（DaBaoAgent/AutoYY，本仓库由其复制而来，已切 remote 至 DaBaoAgent/AutoUP）。

## 1. 定位

纪录片解说**全链路自动生产线**：从人工给定的选题/链接池出发，一键运行到「发布就绪文件夹」，
中途零人工，失败自动断点续传。

## 2. 核心决策（采访结论）

| # | 决策项 | 结论 |
|---|--------|------|
| 1 | 运行形态 | 一键全自动，一条命令选题后跑到成片+发布素材，失败断点续传 |
| 2 | 成品规格 | **8-15 分钟横版长视频**，文案维持 4500-5500 字标准 |
| 3 | 配音引擎 | **双引擎可配置**：默认 GPT-SoVITS（管线自拉起，跑完可关），备用 edge-tts |
| 4 | 音色 | config 可配置多个纪录片解说音色，每次运行可指定 |
| 5 | 画面来源 | **只用源视频切片**：SRT 时间轴把解说句对齐到源片镜头（影子匹配，AutoDSJ 经验） |
| 6 | 解说与原声 | **纯解说压剪**：全程盖解说、不留原声，30min 源片压进对应解说时长 |
| 7 | 字幕 | 烧录中文字幕：描边白字、底部偏上、全程同步 |
| 8 | BGM | 要：本地免版权曲库低音量循环，解说段自动闪避（曲库由 AI 下载 20-30 首） |
| 9 | 平台 | 全平台矩阵：抖音/快手/视频号/小红书/百家号/B站/YouTube/X/IG/FB/TikTok |
| 10 | 发布信息 | **轻量两类**：国内平台（标题≤25字+5标签）、海外平台（英文标题+描述） |
| 11 | 封面 | **三比例全配**：9:16（抖/快/视/红/TK）+ 16:9（B/YT/西瓜）+ 1:1（IG/FB/X），同风格模板 |
| 12 | 自动发布 | 本期不做，但目录/数据结构预留接口（下期接 upload-post 或 playwright） |
| 13 | 选题 | **半自动**：人工给选题清单或 YouTube 链接池，下载环节起全自动 |
| 14 | 字幕兜底 | **只接受 YouTube 自带字幕**，没有英文字幕的选题直接拒，不做 whisper |
| 15 | 分辨率 | 统一 1080p 横版（1920x1080/30fps），源片不足 1080p 时放大 |
| 16 | 批量策略 | **串行**：一次一个选题，跑完再下一个 |
| 17 | 架构 | **混合**：机械环节纯 Python 脚本；LLM 环节（文案/去AI味/发布信息）封装为 API 与 Hermes 双模式 |
| 18 | LLM API | 用现有 GLM API key（zai） |
| 19 | 产出根 | `D:\AutoUP`（新建，与旧 AutoYY 产出 `D:\自动剪辑` 完全分开） |
| 20 | 仓库 | DaBaoAgent/AutoUP（已存在，保留远端 README 与 docs/covers，本地代码覆盖推送） |
| 21 | 调研 | 开发前先调研 MoneyPrinterTurbo / NarratoAI 等高星同类项目的剪辑合成实现，**调研报告先发群里等确认再动工** |

## 3. 全链路阶段

```
选题清单(人工) → ①源核验 → ②下载视频+SRT → ③提取SRT出爆款文案 → ④配音(TTS)
   → ⑤影子匹配+合成剪辑 → ⑥烧字幕+BGM混音 → ⑦发布信息(两类) → ⑧封面(三比例) → ⑨验收打包
```

- ①-② 沿用 AutoYY 已验证方案（manifest + yt-dlp + 断点续传，ffmpeg 在 D:\@佳康顺矩阵\@工具\ffmpeg\）
- ③ 沿用 Humanizer 去AI味强制流程（vendor/blader-humanizer）
- ④⑤⑥ 为本期新开发核心
- 每阶段落盘产物 + 状态标记，支持从任意已完成阶段续跑
